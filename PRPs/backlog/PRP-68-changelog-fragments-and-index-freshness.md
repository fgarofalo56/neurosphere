# PRP-68: Changelog fragments and index freshness

## Goal
Remove the most frequent merge conflict of the parallel build and make the two generated planning files impossible to leave stale. Today every PRP close-out hand-edits the `[Unreleased]` block of `CHANGELOG.md`, always at the top of `### Added`, so two close-out PRs merged on the same day conflict on the same hunk (it happened on 2026-11-14). This PRP replaces that edit with one fragment file per PRP under `changelog.d/`, assembled into `CHANGELOG.md` by a small standard-library script at release time, and makes the CI `planning` job fail when `PRPs/INDEX.md` or `PRPs/EXECUTION-PLAN.md` no longer matches the PRP files. It is for every session that closes out a PRP in waves W11 to W21 and for the operator who cuts a release. It runs in W11 so later waves close out with fragments from the start.

Out of scope: the README, decisions log, gate register, threat model, master prose and the `.githooks/pre-commit` INDEX regeneration step (PRP-36); contract schemas (PRP-37); the release workflow and draft-vs-publish behaviour (`.github/workflows/release.yml`, PRP-63 in W19); the wave plan content and `scripts/prp_execution_plan.py` (orchestrator-owned); the kit script `~/.claude/kits/orchestrated-prp/prp_index.py` and the global `/prp:prp-close` command (outside the repo, owner-side); rewriting the existing `[Unreleased]` entries.

## Why
- `PRPs/reference/parallel-build-reference.md:90` makes `CHANGELOG.md` `[Unreleased]` "hand-written, one entry per PRP, added in the close-out commit only"; `CHANGELOG.md:7-10` shows each new entry inserted directly under `## [Unreleased]` / `### Added`, so every close-out touches the same lines (the PRP-09 and PRP-25 round-2 close-outs, `7d22d10` and `7ff2aa7`, both landed there on 2026-11-14).
- The global close-out command `~/.claude/commands/prp/prp-close.md:37` also says "add a line under `[Unreleased]`"; 28 of the 35 files in `PRPs/backlog/` mention `CHANGELOG` in their close-out item. The repo rule has to say what replaces it.
- `PRPs/INDEX.md:1` is generated by `~/.claude/kits/orchestrated-prp/prp_index.py build`, which is not in the repository; CI runners do not have it, and the `planning` job (`.github/workflows/ci.yml:160-189`) runs only `scripts/validate_planning.py`, the licence register and the `|| true` scan.
- `scripts/validate_planning.py:196-206` checks the master status table through `scripts/prp_status.py --check`, but nothing checks `PRPs/INDEX.md`; `scripts/prp_execution_plan.py:270-279` has a `--check` mode that no workflow or hook calls.
- Release notes do not read `CHANGELOG.md`: `.github/workflows/release.yml:333` builds them from commits with `scripts/release/changelog.py`, and `docs/release/release-process.md:12-37` says the Unreleased block is curated by hand into the version section. Fragments can therefore be assembled at release time without changing the release workflow.

## Acceptance criteria
- [ ] Given a fragment `changelog.d/<PRP file stem>.md` (or `changelog.d/issue-<n>.md` for a change with no PRP) whose body uses only the Keep a Changelog headings `### Added|Changed|Deprecated|Removed|Fixed|Security` with list items under them, when `python scripts/changelog_assemble.py --check` runs, then it exits 0; a fragment with another heading, no list item, a bad file name or a `## ` heading exits 1 naming the file and the rule.
- [ ] When `python scripts/changelog_assemble.py --write` runs, then every fragment's items are spliced into the `[Unreleased]` block under the matching heading (headings created in Keep a Changelog order when missing; fragments in sorted file-name order), every existing byte of the block is kept, and the fragment files are deleted; `--preview` prints the result and changes nothing; with no fragments `--write` is a no-op that exits 0.
- [ ] The assembler reuses the Unreleased-block boundary rule of `scripts/release/changelog.py` (`UNRELEASED_RE`, `NEXT_HEADING_RE`) instead of a second definition, and uses only the standard library (no new dependency, licence register unchanged).
- [ ] Given a PRP file under `PRPs/backlog/`, `PRPs/active/` or `PRPs/shipped/` that is missing from `PRPs/INDEX.md`, listed in the wrong section, listed twice, or a backlog row whose priority, order or review differs from its frontmatter, when `python scripts/validate_planning.py` runs, then it fails naming the PRP; the current `main` passes.
- [ ] The CI `planning` job runs `python scripts/prp_execution_plan.py --check` and `python scripts/changelog_assemble.py --check` as separate named steps (no `|| true`), and the INDEX check runs inside `validate_planning.py` (so `tests/test_planning_alignment.py` also enforces it).
- [ ] `docs/release/release-process.md` step 2 runs the assembler before `scripts/release/changelog.py` and says the fragments are committed in the release PR; `PRPs/reference/parallel-build-reference.md` section 2 Tier-3 table says close-outs write `changelog.d/<PRP file stem>.md` and never edit `CHANGELOG.md`, the INDEX row names the CI check, and section 6 close-out step 2 adds the fragment.
- [ ] `changelog.d/README.md` (new) documents the file name rule, allowed headings, one example, and that the global `/prp:prp-close` "add a line under `[Unreleased]`" step is replaced by a fragment in this repository.
- [ ] `[serial-after: PRP-36]` `.githooks/pre-commit` blocks a commit with a malformed staged fragment and prints a warning (no block) when `PRPs/EXECUTION-PLAN.md` is stale; `bash -n .githooks/pre-commit` passes.
- [ ] This PRP's own close-out writes the first fragment instead of editing `CHANGELOG.md`.

PRP exit: every box ticked, the tests named in the items pass, `python scripts/validate_planning.py` and the `verify-gates.ps1` full run green, PR open, CI `planning docs aligned` green with the new steps visible in its log.

## Migration and rollback
No data or schema change. Existing `[Unreleased]` entries stay where they are; fragments are additive. Rollback is `git revert` of the PR: the two CI steps and the INDEX check disappear, and any fragments written meanwhile can be assembled once by hand with the reverted script from git history or pasted into `CHANGELOG.md`. To turn the INDEX check off without a revert, remove the `check_index_file()` call in `validate_planning.py`.

## Live and open gates
None. No cloud call, no `NS_LIVE_APPROVED=1`, no paid call. The first real release that uses the assembler is an operator step (release-process step 2) and stays OPEN until a release is cut.

## NOT building
- towncrier or any other new dependency.
- A merge-time bot that writes `CHANGELOG.md` on `main`.
- Changes to `release.yml`, release notes or draft publishing (PRP-63).
- A vendored copy of the kit's INDEX renderer, or byte-exact INDEX comparison in CI.
- Edits to the global kit or `/prp:prp-close` command, or to other backlog PRP files that still mention `CHANGELOG` (the reference rule overrides them).
