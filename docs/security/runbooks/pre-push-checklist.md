# Pre-push checklist

A push is publication. This list mirrors what `.githooks/` and
`.github/workflows/secret-scan.yml` actually enforce; it adds human judgement
on top and invents no extra automated check.

## Once per clone

- [ ] Run `bash scripts/install-git-hooks.sh`.
- [ ] Confirm `git config core.hooksPath` prints `.githooks`.

## Before you commit (pre-commit enforces on the staged diff)

- [ ] No `.env`, `.env.*` (except `.env.example`), `*.pem`, `*.key`, `*.pfx`,
      `*.p12`, `*.jks`, `*.keystore`, `*_rsa`, `*_ed25519`, `.netrc`, `.pgpass`,
      `credentials.json`, `service-account*.json`, `azure.json`,
      `*.publishsettings`, or anything under `secrets/`.
- [ ] No secret-shaped content: AWS key ids, GitHub tokens, LLM API keys, Slack
      tokens, private key blocks, JWTs, Azure storage or Event Hubs connection
      strings, or hardcoded `password`/`secret`/`api_key`/`bearer` values.
- [ ] No SSN-shaped or payment-card-shaped numbers (pre-commit, pre-push and CI).
- [ ] Python staged: `ruff check` and `ruff format --check` pass (pre-commit
      runs them when `uv` and `pyproject.toml` exist).
- [ ] PRP files staged: the PRP status table is regenerated by the hook.
- [ ] Placeholders look like placeholders (`<vault-name>`, `example`, `your-...`);
      the hooks skip lines matching their placeholder filter.

## Before you push (pre-push enforces over the whole pushed range)

- [ ] Same patterns and credential-shaped filenames, scanned across every commit
      in the range, not just the tip.
- [ ] Review the range yourself: `git log --stat origin/main..HEAD`.
- [ ] Nothing from `temp/` or generated output is tracked.
- [ ] Operator approval for the push itself; never force-push.

## What CI checks regardless (`secret-scan.yml`)

- gitleaks over **full history** with `.gitleaks.toml` and `.gitleaksignore`.
- No tracked credential-shaped file paths.
- No SSN/card patterns anywhere (except the scanners' own files).
- Weekly scheduled re-scan with newer rules.

Optional local equivalent of the CI gate:
`gitleaks git . --config .gitleaks.toml --redact --no-banner`

## Bypass warning

`git commit --no-verify` and `git push --no-verify` skip the local hooks, and
hooks only run on machines that installed them. The CI full-history scan is the
backstop; do not rely on it as permission to bypass. If a real secret got
through, stop and follow [credential-leak-response.md](credential-leak-response.md):
rotate first, then clean history.
