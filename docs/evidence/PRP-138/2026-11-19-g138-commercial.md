## Not proven

- **The mapping as the only source of admin.** The operator's account also holds a stored `admin` grant (the 2026-11-18 `seed-access` re-grant). The "Entra app role" row proves the mapping was applied to the token; it does not prove the Admin pages open for a user with the app role and no stored grant. That needs a second user, or the same check after the stored grant is revoked or expires.
- **Wire-level view.** The page content was read after load; the API responses behind it were not captured.
- **Domains beyond the control domain.** The mapped role lists 1 domain because the domain registry of this deployment is empty; registered domains are added by the server once they exist (PRP-139).
- **`entra_admin_mapping.py apply` and `verify`** were not run: nothing needed applying, and the browser check replaced `verify`. Whether `az account get-access-token` can obtain a token for the API app stays UNVERIFIED.
