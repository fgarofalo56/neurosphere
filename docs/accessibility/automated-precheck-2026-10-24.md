# Automated pre-check (2026-10-24)

This is an automated pre-check. It is not a human test and does not replace the signed keyboard and screen reader checklists. Every row in `keyboard-checklist.md` and `screen-reader-checklist.md` stays `Status: OPEN (unsigned)`. Nothing here is a conformance, VPAT or Section 508 statement.

What it is for: a machine drives real keys (`page.keyboard`) and reads the accessibility tree through Playwright, so the human tester can confirm quickly instead of discovering basic breakage. PASS means the automated checks of that row passed. It does not mean the experience is acceptable, that a screen reader announces the content well, or that the focus order is logical.

## Method

- Key flows: one test per checklist row, real key presses, each check recorded separately.
- Route sweep: for every route in the manifest (one sample per pattern, shared with the axe spec), in light and in the high-contrast theme, Tab through up to 80 stops. Asserted: every stop is a visible element in the viewport; every stop shows a focus indicator; focus is never stuck on one element and never cycles inside a small subset of the page; the page has a visible h1. Fluent's aria-hidden `[data-tabster-dummy]` sentinels are skipped, not counted.
- Focus indicator method: the focused element, or an ancestor within 3 levels that matches `:focus-within`, has a real outline or a box-shadow; or the same nodes' `::after` / `::before` (when they generate content) have an outline, box-shadow or border; or a descendant up to 2 levels down has an outline (Fluent Tree items). A bare Fluent attribute (`data-fui-focus-visible`) is not accepted, because it proves the library flagged the element, not that a ring is painted. This is a computed-style heuristic: it cannot judge colour contrast of the ring or whether it is thick enough to see.
- Accessibility tree: `getByRole` with the exact product names and `toMatchAriaSnapshot`. The route rows check the page title, one main landmark with an h1, the banner and Primary navigation landmarks, and that no control in the body's aria snapshot lacks a name.
- Focus order is not judged. Chromium headless does not drive NVDA, Narrator or VoiceOver.

Run totals (before the item 5b fixes): 505 checks, 497 passed, 3 failed, 5 notes; all pass after A11Y-013 and A11Y-014 were fixed.

## Checklist wording differences (reported, not guessed)

- Sandbox toggle: the checklist says the switch is announced 'On: synthetic data only' or 'Off'. The product labels it 'Sandbox mode' and exposes on and off through the checked state only. `toggleOn` and `toggleOff` in `frontend/src/features/sandbox/strings.ts` are defined and not rendered.
- Map page: the checklist says the region is named 'Agent topology map'. The product name is 'Agent topology map (WebGL graphic). The table view is the accessible equivalent.'
- Chart table: the checklist says 'caption'. The product gives the table an accessible name through `aria-label`, not a `<caption>` element.
- Actions dialog: 'Review and confirm' is the trigger button. The dialog title is 'Confirm this change' and its role is `alertdialog`.
- Primary navigation: the landmark has role `navigation` named 'Primary' (found by role), but it renders as a `div` with an ARIA label, not a `nav` element.
- User menu trigger: Fluent sets `aria-haspopup=menu` and `aria-expanded=true` while open; the attribute is absent (not `false`) while closed.
- Reports list: columns are Title, Publication, Updated. The owner is shown inside the title cell, so there is no Owner column header.

## Behaviour notes from the keyboard flows

- Chart tabs use manual activation (WAI-ARIA tabs pattern): arrow keys move focus, Enter or Space selects. The pre-check asserts that behaviour. A tester who expects automatic activation will see a difference.
- Escape does not close the copilot panel while focus is inside the chart iframe (key events do not leave the opaque-origin frame). The Close button and Escape from anywhere else work. Not logged as a defect: Tab leaves the frame.
- One transient failure was seen once in four full runs on `/workspaces/auditor` (light); three isolated reruns passed. The failing detail was not captured. If it recurs, the record in `precheck-results.json` carries the offending element.

## Not covered by any automated check

- Spoken output of NVDA, Narrator and VoiceOver, and the AT matrix.
- Logical focus order, meaningful labels, and whether the experience is understandable.
- The WebGL map canvas, the content inside the sandboxed chart iframe, and the Save as report dialog.
- Status and error text being announced.
- The sign-off blocks: Tester, Date, Assistive technology, AT version, Browser and OS stay empty until a human completes them.
